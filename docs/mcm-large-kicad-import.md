# MCM 与大型 KiCad 文件导入修复

日期：2026-11-04。读取用户提供的文件验证，未修改源文件。

## 修复内容

- `.mcm`（大小写均可）接入已有 Cadence/Allegro 二进制读取器，保留布局版本、连接、层、焊盘、过孔、走线、铜皮和源文字。继续检查文件头，不按扩展名强行解释任意数据。
- KiCad 原先为整块板构建拥有全部字符串的语法树，并把全板文本项限制为 1,600 万。`DDR5.kicad_pcb` 在此失败：`IMPORT_RESOURCE_LIMIT actual=16000001 limit=16000000`。
- 现在先建立紧凑的顶层表达式字节范围索引，再逐个解码所需对象。保留输入大小、单对象文本项、嵌套深度、根对象数量和取消检查；不删除大文件中的绘图对象来规避限制。
- 导入后还发现绘图拾取索引按“结构大小 + 512 字节”逐项估算，另有独立 256 MiB 上限。改为按排序键、字形副本和空间层次索引的实际分配阶段计算峰值，服从整个拾取索引的总预算。排序键缩减，保留原先每层 16,384 段分批、直线先于圆弧的提交顺序。
- GPU 读回还发现整板范围被 `User.34` 层半径约 4,255.6 mm 的辅助圆撑开。闭合的 `Edge.Cuts` 现在优先定义板范围；没有完整闭合板框时继续采用原先全部几何的范围。辅助图形仍完整保留，可平移查看，不删除或改写源数据。

DDR5 文件为 698,116,776 字节，另有 1,855,973 个绘图对象。桌面准备得到 1,890,759 段绘图笔画、6,964,787 段铜皮边界，受管理的渲染准备输出为 1,251,329,692 字节；这个数字不包含源模型、拾取索引、字体或 GPU 内存。ARM MCM 对应的准备输出为 985,100,360 字节。

专用验证测试为 `document::preparation::tests::local_native_boards_prepare_for_the_desktop`，通过 `POMELO_DOCUMENT_CASES` 指定本地文件列表后运行；样本不复制进仓库。该检查验证桌面导入链路，不等同于所有图层的 GPU 像素验收。

另使用硬件 D3D11 完成 DDR5 和 `LPDDR5_PKG.mcm` 的原生几何上传、绘制和像素读回。DDR5 板框范围约为 428 × 388.65 mm；检查修正后的整板图像，PCB 不再被远处辅助圆挤到角落。该诊断关闭源文字、动态标注和 GPUI，验证范围明确限于几何绘制。诊断入口 `hardware_real_board_frame_profile` 现支持通用格式调度，可设置 `POMELO_FRAME_PROFILE_FIT_ONLY` 只运行整板视图，输出目录同时保存 RGBA 和 PNG。

## 回归与已有边界

- 表达式扫描回归覆盖 BOM/空白、引号内括号、Unicode 路径、截断字符串、非法根结构、深度限制、取消，以及超过旧全板文本项上限的跳过数据。
- 绘图索引回归验证密集对象能在实际所需预算下建立索引、形成正确拾取命中，同时仍拒绝不足的总预算。
- 此次没有扩展原先未实现的 KiCad 文字、封装绘图/文字和填充图形呈现。DDR5 仍保留 153 条对应既有能力边界的诊断；“导入链路通过”不表示这些显示特性已补齐。
- `validate_native_formats` 示例保留固定默认资源限额，DDR5 的 696 万段铜皮边界会超过该示例的 400 万段上限。大型文件的应用验收使用上述真实桌面准备测试，而不是把示例上限作为应用能力结论。

格式参考：[KiCad 官方板文件格式](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/)。具体样本数据和验证结果以上述本地文件与日志为准。
