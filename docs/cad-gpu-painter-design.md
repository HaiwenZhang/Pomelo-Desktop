# GPU 绘制架构

## 数据流

```text
文件导入 → 领域场景 → 几何与批次准备
                        ↓
               不可变帧快照与资源版本
                        ↓
              GPUI 画布注册及绘制入口
                        ↓
            D3D11 / Metal / wgpu 后端
                        ↓
               当前窗口目标与统一呈现
```

领域模型和几何算法属于应用。GPUI 管理窗口、布局、场景顺序及帧提交；渲染 crate 管理业务着色器、批次、缓冲区和缓存。三端共享画面语义，各自实现平台资源及命令。

## 帧目标

回调使用当前帧借用的设备、编码器和颜色目标。完整 bounds 用于视口和相机，有效 clip 用于裁剪，DPI 用于物理像素换算。透明度与颜色空间约定须与 GPUI 合成一致。

主画面接入当前窗口目标。必要辅助附件由应用管理，不另建应用交换链；回调不自行提交或呈现，不跨帧持有目标，也不重入 GPUI 绘制。

## 准备与缓存

CPU 在后台准备网格、实例、文字与索引，结果通过版本和请求身份发布。每帧读取显示快照，按版本更新资源，避免遍历或复制全部源几何。

几何、文字、标签和曲线缓存分别失效。上传预算与 CPU 准备预算分开，取消请求及时停止无用工作。空几何与空覆盖是合法结果，应明确其替代和跳过语义。

## 生命周期与错误

窗口销毁或设备替换时释放关联 GPU 资源，恢复后按有效场景重新建立。编码器在回调返回前结束，不能把回调完成当作 GPU 完成或已经呈现。

错误展示不改变画布尺寸，避免错误与布局反复触发缓存失效。保持结构化诊断和明确恢复行为，不因失败静默显示过期内容。

## 验证

从合成三角形、线段、带孔区域和文字开始，覆盖 UI/GPU 绘制顺序、裁剪、DPI、透明度、窗口调整及设备恢复。大场景再验证增量上传、缓存和持续交互。各平台结果分别记录，方法见[验证指南](validation-guide.md)。
