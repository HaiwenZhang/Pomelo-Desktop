# PCB 三维渲染实施方案

状态：实施方案，尚未交付。三维查看作为独立开发方向，沿用 Pomelo 的只读文档、后台准备和原生 GPU 架构。

PCB 板体、铜层和孔采用二维轮廓加物理高度生成三角网格，直接交给 GPU 绘制。第一阶段不要求将整板转换成 B-rep；STEP 元件导入可通过独立适配模块解析 B-rep 并三角化，后续整板 STEP 导出另行设计。

## 目标与范围

实现与二维画布共享源对象身份的三维查看：板体厚度、开槽及钻孔、铜层、焊盘、走线、元件，以及旋转、缩放、选择和属性联动。继续保持源设计只读，三维显示设置和用户补充信息保存到本地查看配置。

按阶段加入物理叠层、层展开、剖切、阻焊和丝印。初期使用简单实时光照；PBR、阴影、物理折射和路径追踪不作为第一阶段交付条件。三维显示不自动提供 DRC、制造检查、精确碰撞或 SI/PI 仿真结论。

完整装配外观与板内结构检查分别组织：前者优先显示板体、外层和元件；后者允许隐藏介质、逐层查看和展开。两者消费同一份领域数据，避免各自产生不同的物理结构。

## 几何表达与数据流

领域层保留原始解析曲线、物理参数和源身份。网格是按指定精度生成的派生缓存，不成为源设计的替代品，也不作为精确制造尺寸的权威数据。

```text
文件导入
  → BoardScene 与可选物理叠层、孔深、元件模型信息
  → 解析源值和本地显示假设
  → 轮廓规范化、材料区域运算、三维网格和空间索引
  → 不可变三维场景及资源版本
  → GPUI 当前帧的原生 GPU 绘制入口
  → 深度测试、着色、对象高亮与界面覆盖层
```

### 坐标与物理参数

三维场景统一使用毫米、弧度、右手坐标和 Z 向上。以板体厚度中心为 Z 零点，顶面为 `+t/2`，底面为 `-t/2`。导入适配模块负责源坐标转换，绘制后端不再判断源格式的 Y 方向或角度符号。

物理叠层保存有序的导电层和介质层。每层的 `z_min`、`z_max` 由厚度累加得到，导电层关联已有 `LayerId`；介质层具有自己的身份，不能伪装成铜层。二维显示面板的绘制优先级和用户层序不改变三维物理高度。

每个物理值区分源文件给出、用户补充、显示假设和未知。源文件缺失时可使用可编辑的显示板厚，例如 1.6 mm，但必须将其标记为假设；不能把图层数均分后的高度宣称为真实叠层。对源板厚和层厚总和冲突进行诊断，不静默缩放源数值。

现有 `mirrored` 字段参与二维变换，但三维模型应显式记录安装面。背面安装包含翻转和局部变换约定，不能仅使用 XY 镜像；各源格式通过合成数据验证顶底面映射。

### 网格与对象身份

网格保存位置、法线、三角形索引及必要的边线。位置计算和轮廓运算使用 f64；上传时以板中心或批次局部原点转换为 f32，并验证范围。复用项目已有的高低位坐标经验，避免远离原点的板坐标丢失精度。

三角形或批次通过独立映射关联对象类别、`ObjectId`、可选 `LayerId`、可选 `NetId` 和表面角色。板体、介质和元件分别有类型化身份；生成的孔壁关联原始孔对象，不能用临时顶点编号冒充源对象编号。共用一个元件网格的不同实例保留各自的封装身份。

GPU 材质与对象身份分别保存。颜色变化不重建几何；网络选择依据身份改变显示，不能通过颜色反查对象。

## 网格生成

### 板框和材料区域

先把板框中的线段和圆弧连接成闭合环。端点匹配使用毫米容差和有界空间查询，检查断裂、重复边、自交以及含糊连接；不得为了显示完整板体而自动连接远处端点。

曲线按弦高误差自适应采样。三维实体网格采用模型空间精度，不随每次相机旋转重新生成；需要多个精度档位时以档位作为缓存键。屏幕空间采样可用于显示轮廓，但不能改变孔径或材料区域。

根据环的包含关系区分外轮廓、开槽和材料岛。对相交孔、边缘缺口及相切轮廓先进行二维区域运算，得到无自交、孔洞关系明确的材料区域，再三角化。仓库已有 `earcut` 可用于有效多边形及孔洞；它不承担拓扑修复或区域布尔运算。区域运算依赖在实现时单独评估精度、许可、资源限制和退化行为。

第一阶段可限制为单个板体外环、合法内部开槽及互不相交的通孔。遇到不支持的板框给出结构化诊断；二维视图仍可使用，三维视图不生成看似完整的错误板体。

### 板体和钻孔

对扣除开槽、通孔后的材料区域三角化，把顶点复制到上下表面，并以相反绕序生成底面。每条轮廓边连接上下节点形成侧壁；内孔侧壁的朝向与外板边相反。上下表面和侧壁可以使用不同顶点法线，以保留锐利板边。

普通圆孔和长圆槽依据 `DrillShape`、位置、旋转及源变换生成截面。不能用焊盘内径替代钻孔尺寸。镀铜孔壁使用内外轮廓表示金属厚度，未知厚度保留假设状态；无镀铜孔不生成铜筒。

盲孔、埋孔和背钻只影响实际加工深度覆盖的层段。其网格生成需要沿 Z 的材料截面分段，连接各段侧壁，并生成盲孔底部及厚度变化处的封闭面；仅在顶底表面扣孔无法表达这些结构。加工层范围未知时不扩展成通孔。局部叠层、阶梯槽和刚柔结合板在有完整区域数据和对应算法前保留为后续能力。

### 走线和焊盘

走线由中心线、线宽和端头规则生成二维导电轮廓，圆弧保留解析信息并按精度离散。焊盘复用现有形状和变换逻辑，包括自定义轮廓和偏移。两者放到所属导电层高度。

第一阶段外层铜可作为表面几何绘制，用有限深度偏置解决共面闪烁；偏置只影响显示。显示铜厚、截面或展开视图时，沿真实或明确假设的铜厚挤出上下表面和侧壁。

一个层内重复或重叠的导电图形需要明确覆盖规则：初期可分批绘制，避免共面高亮和透明重复叠色；生成封闭铜实体和准确截面时需先合并该层材料区域。按孔的物理范围处理其与铜的交集，避免铜面跨过实际孔洞。

### 铜皮及孔洞

当前 [`geometry/copper.rs`](../crates/pomelo-core/src/geometry/copper.rs) 和 [`scene/copper.rs`](../crates/pomelo-render/src/scene/copper.rs) 将外轮廓和孔独立三角化，通过覆盖或模板规则实现外区域减去孔的并集。部分轮廓还使用奇偶覆盖。

这些二维批次不能作为普通三维填充网格全部绘制或挤出，否则孔会被填满。三维网格生成必须按现有覆盖语义得到最终材料区域，处理重叠孔、相交孔及材料岛，再三角化并连接侧壁。只需要平面外观时可另设覆盖绘制路径，但不能把它当作封闭铜实体、剖面或体积数据。

### 阻焊与丝印

阻焊使用板面覆盖减去源阻焊开窗。丝印以表面图形或贴花绘制，并按明确规则与阻焊及焊盘开窗相互作用。没有阻焊开窗数据时，仅提供标为近似的外观；不从所有焊盘统一推断开窗并宣称制造还原。

阻焊和丝印首先作为表面层实现，避免为细小文字大量挤出实体。内层和展开视图以几何层为主，外观贴图不能替代可选择的铜对象。

## 元件模型

元件模型通过独立导入模块转换成统一网格。第一步支持简单模型或可验证的网格格式；STEP 支持在独立阶段实现，不将 STEP 解析依赖传入核心场景和 UI。

同一模型只解析和上传一次，以实例矩阵放置多个封装。实例变换由源格式适配模块组合模型局部缩放、旋转、偏移、安装面变换和封装位置；明确矩阵顺序与坐标约定。若使用反射矩阵，还需处理法线的逆转置变换和三角形绕序。

缺失模型显示标为占位的外形或仅显示封装信息，不生成具有未知高度的真实外观。模型路径、单位或旋转无法解析时报告对应元件，板体仍可查看。使用本地路径映射处理模型库；不在绘制过程中访问磁盘或下载模型。

模型缓存绑定内容、解析器版本、单位和网格精度。重载及设备恢复分别处理 CPU 解析结果和 GPU 资源，不因设备丢失重新解析所有源模型。新增模型、纹理和字体保留明确的来源及许可记录。

几何准备模块对外提供一个主要入口：输入领域场景、解析后的物理参数、精度与资源限制、取消令牌，返回准备后的三维场景或结构化错误。轮廓修复、孔段连接和三角化留在模块内部，调用方不承担这些顺序要求。

结果包括网格及实例、对象映射、包围盒、物理信息来源、局部未支持项和资源统计。取消、超预算、无效输入与局部对象缺失分开表示；明确哪些问题使板体不可用，哪些允许缺少元件继续显示。

不直接依赖整套 SolidCraft engine、doc 或 UI。若抽取通用几何代码，隔离为 Pomelo 自己的模块或独立库，并保留对应许可和署名；CAD 特征树、约束求解及参数重建不进入 PCB 查看路径。

## GPU 绘制与交互

### 原生后端接入

沿用 [ADR 0001](adr/0001-native-gpu-rendering.md)：Windows 使用 D3D11/HLSL，macOS 使用 Metal/MSL，Linux 使用 wgpu/WGSL。复用 GPUI 当前设备和帧目标，不创建独立交换链，也不在回调内自行提交或呈现。

三维绘制使用应用管理的深度附件。现有二维路径的模板附件和深度禁用状态不能直接满足三维遮挡；三个后端分别补齐附件格式、深度清除、比较、写入及管线状态。附件尺寸与当前目标物理像素、采样数一致，回调使用完整 bounds 计算投影和有效 clip 设置 scissor；不能清除同一帧中已经绘制的 GPUI 颜色内容。

帧目标只在当前回调内借用。窗口尺寸、DPI、目标格式、采样数或设备改变时重建相关附件和管线，并通过 GPUI 的生命周期释放旧资源。

基础顶点包含位置和法线；材质、对象映射及实例矩阵分别组织。三端维护一致的矩阵布局、颜色空间、透明度约定和三角形绕序，并用同一组合成场景验证。

### 绘制顺序与光照

1. 绘制不透明板体、可见铜面和元件，开启深度测试及写入。
2. 绘制透明介质及元件，开启深度测试并关闭深度写入；初期按深度排序，复杂相交透明体保留明确限制。
3. 绘制深度测试的边线、选中面和网络高亮；采用有限偏置避免闪烁。
4. 绘制坐标轴、标签、测量和导航覆盖层，区分被模型遮挡与始终可见的语义。
5. 保持 GPUI 面板、菜单及弹窗的正常合成顺序。

第一阶段采用环境光、方向主光和高光。玻璃或透明板材首先只表示 alpha 混合，不宣称物理折射。真实铜厚与板厚比例很小，视觉强调通过独立显示选项处理，不改变领域尺寸。

### 相机和拾取

三维相机支持轨道旋转、平移、鼠标附近缩放、适应整板、顶底视图和透视/正交切换。相机状态属于当前文档，二维与三维切换保留各自的导航位置。裁剪面依据当前场景范围设置，避免铜层间深度精度不足。

拾取由屏幕射线进入场景，先筛选对象包围盒，再通过 BVH 或其他有界空间索引测试三角形。网格误差决定显示命中的精度；属性中的孔径、线宽和尺寸读取源参数。元件实例的射线转换到网格局部空间，共享索引不改变实例身份。

命中结果映射到现有类型化选择。没有源对象的板体或介质命中使用三维专用目标，不生成虚假的二维对象。隐藏对象不参与普通拾取；透明、穿透选择和展开模式有一致规则，并能列出重叠候选。

展开视图使用独立的层或实例变换，保持物理层位置可查询。拾取、定位及标签消费同一显示变换；距离或高度属性仍报告物理坐标，不把展开距离当成真实尺寸。

剖切分为隐藏片元和生成剖面两项能力。只有隐藏片元时称为裁剪；要显示填充剖面、孔边界及分层截面，还需截面轮廓和封闭填充。复杂层展开、盲孔及多材料截面在专门阶段验证。

## 缓存与后台任务

| 变化 | 更新范围 |
| --- | --- |
| 相机旋转、平移和缩放 | 相机参数、必要透明排序及可见性，不重建静态网格 |
| 悬停、选择、网络高亮 | 对象映射和高亮参数 |
| 颜色、透明度与层可见性 | 材质、批次可见性和绘制顺序 |
| 展开距离 | 层及实例显示矩阵 |
| 板厚、叠层、孔深或几何精度 | 依赖这些值的板体、铜和孔网格及其索引 |
| 元件模型或局部变换 | 对应模型资源或实例矩阵 |
| 文档重载 | 核对源身份，失效相关准备结果 |
| GPU 设备替换 | GPU 资源；有效 CPU 场景继续复用 |

网格准备在后台执行，沿用 [`task.rs`](../crates/pomelo-core/src/task.rs) 的取消令牌及文档请求身份。切换、重载或关闭文档后，旧结果不得发布到新视图。分批发布明确版本和完成状态，未完成或缺失几何不以旧版本替代。

轮廓采样、区域运算、三角化、空间索引、模型解码和上传分别设置工作量及内存限制。预留 CPU 输出、算法临时数据和 GPU 驻留预算；单次不可中断的依赖调用需限制输入规模。达到限制时返回诊断，不能无限细分或在 UI 绘制路径等待。

## SolidCraft 参考模块

以下为参考仓库中的路径；移植时核对对应代码版本和许可。主要复用数学、数据组织和验证方法，GPU 接入按 Pomelo 的 GPUI 架构实现。

| SolidCraft 路径 | 参考内容 | Pomelo 的适配方式 |
| --- | --- | --- |
| `crates/geom/src/profile.rs` 的 `Loop2`、`Region2` | 解析边界、带孔平面材料区域 | 接收走线轮廓、逐层焊盘和 Zone 最终填充区域，保留源对象与网络身份 |
| `crates/kernel/src/prism.rs` | 平面区域布尔、带孔区域挤出及按高度截面处理棱柱布尔 | 优先评估铜层、孔段和背钻的分段构造；不能把通用三维布尔作为每个过孔的必经步骤 |
| `crates/kernel/src/build.rs` 的 `extrude` | 从带孔轮廓及起止高度构造实体 | 参考铜厚、板厚与中空孔壁的构造；按层和局部区域准备，不默认合并整板为一个实体 |
| `crates/render/src/camera.rs` | 轨道相机、投影、标准视图、屏幕坐标和拾取射线 | 适配为独立三维相机；核对三端矩阵和源坐标转换 |
| `crates/geom/src/mesh.rs` | 索引网格、法线、包围盒、三角形身份及射线命中 | 将 CAD 面编号映射改为 PCB 对象、网络、层和实例身份；大场景增加空间索引 |
| `crates/ui-egui/src/gpu.rs` | 不透明、透明、边线、高亮和预览的绘制组织；分批缓存 | 借鉴管线和缓存语义，使用 Pomelo 已有原生后端 |
| `assets/shaders/viewport.wgsl` | 实时光照、轮廓线、透明和裁剪 | 保持三端语义一致，实现对应 MSL、HLSL、WGSL |
| `crates/ui-egui/src/viewport.rs` | 包围盒筛选、拾取过滤、对象映射和高亮 | 接入 Pomelo 现有搜索、选择和属性面板 |
| `crates/doc/src/eval.rs` 的 `ModelBody` | 不可变实体、延迟生成和共享缓存 | 缓存 PCB 派生网格；不引入 CAD 时间线 |
| `crates/render/src/raster.rs` | CPU 光栅器、快照和遮挡参考 | 作为可选的无窗口预览及验证工具，GPU 仍需独立像素测试 |
| `crates/kernel/src/tess/` | 共享边界采样、误差细化及法线朝向 | 借鉴边界一致性；PCB 平面挤出不需完整曲面求值管线 |
| `crates/kernel/src/step_in/` | STEP 几何、元数据及装配读取 | 后续评估独立元件导入适配模块，验证实际覆盖范围 |

参考仓库：[SolidCraft](https://github.com/bherbruck/solidcraft)。SolidCraft 的 GPU 计算曲面求值针对参数曲面网格；PCB 平面挤出第一阶段使用 CPU 准备即可，先测量瓶颈再决定是否增加 GPU 几何生成。

源码核对与另一参考实现 usd-brep 的接入评估见[三维几何参考实现](pcb-3d-reference-implementations.md)。SolidCraft 的平面布尔保留直线和圆弧，但自由曲线可能按容差近似；其输入和处理预算不能直接当成整板 PCB 的容量保证。直接依赖 kernel 还需处理其 workspace 中的 truck 补丁和依赖闭包。先用全层走线、Zone、逐层焊盘及中空过孔的合成场景比较几何正确性、准备耗时与内存，再决定采用独立网格构造、提取算法还是接入实体内核。

usd-brep 的 `SM_API` / `SMLib` 可作为另一实体几何后端候选，已有带孔建面、平面布尔、线性挤出、圆柱、实体差和三角化接口。只评估几何与网格提取，不要求接入 USD、Python 或 Hydra。其公开接口是 C 风格 C++，Rust 接入需要薄桥接层，逐入口处理所有权、失败及默认全局 context 的并发限制。实体面编号仍需转换成 Pomelo 的源对象、层与网络映射；这些接口的存在不代表整板几何规模和三平台构建已验证。

## 实施阶段

每个阶段完成领域逻辑、后台处理、真实 UI 入口、五语消息、状态策略和对应验收。三平台绘制结果分别验证，不以一个平台通过推断其他平台可用。

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| 1 三维视口基础 | 三维模式入口、相机、三角网格管线、深度附件和简单光照 | 合成长方体可旋转，前后遮挡正确；菜单裁剪、DPI 和窗口缩放正常 |
| 2 板体与通孔 | 合法板框、内部开槽、圆孔及长圆孔；源板厚读取和显示假设 | 上下表面、板边及孔壁闭合；缺失或无效板框有明确诊断 |
| 3 外层铜与联动 | 顶底走线、焊盘、铜皮和孔扣除；三维拾取及网络高亮 | 铜皮孔不填满；二维与三维选中同一源对象；背面方向正确 |
| 4 物理叠层和孔段 | 内层、铜厚、盲埋孔、背钻及层展开 | 高度由叠层决定；孔只影响其深度范围；假设与源数据区分 |
| 5 元件装配 | 模型引用、异步加载、实例缓存、正反面放置和缺失占位 | 重复元件共用网格；变换、单位、取消及缺失模型均有验证 |
| 6 工程查看完善 | 阻焊开窗、丝印、剖切填充、截图和查看状态迁移 | 开窗和截面边界正确；保存恢复、多文档和设备恢复可用 |

STEP 元件支持可作为阶段 5 的独立子任务交付。实施阶段 1 时先在可运行的本机后端建立闭环，再完成其他后端的同等能力；未验收平台在交付记录中明确列出。

第一批具体改动是增加三维相机、统一三维网格结构及 `PreparedBoard3d` 准备入口，接入 GPUI 三维绘制回调，并用合成板框验证厚度和通孔。不要同时展开 STEP、复杂材质和通用实体布尔运算。

## 验收与回归

| 范围 | 合成用例及断言 |
| --- | --- |
| 板体几何 | 矩形、凹形、圆弧板边、内槽及材料岛；检查边界、朝向和退化三角形 |
| 面积和体积 | 板材面积等于外区域减开孔；简单挤出体积等于材料面积乘板厚，圆弧误差按采样精度设容差 |
| 孔 | 圆孔、旋转长圆孔、孔交叠和边缘缺口；盲孔底部、埋孔、镀铜及背钻范围 |
| 铜 | 重叠孔的并集、窄铜桥、自定义焊盘、材料岛和源覆盖语义；孔内无铜面三角形 |
| 变换 | 源 Y 方向、旋转、顶底安装、局部缩放偏移、反射法线及重复元件实例 |
| 物理信息 | 缺失厚度、层厚总和冲突、未知孔范围、用户覆盖和显示假设 |
| 拾取 | 前后遮挡、隐藏层、透明候选、展开变换及正确对象、网络和层身份 |
| GPU | 不透明深度、透明顺序、共面闪烁、裁剪、颜色、覆盖层和 DPI；三端像素检查 |
| 生命周期 | 取消、重载、快速切换、关闭文档、窗口缩放、设备重建和资源释放 |
| 状态与 UI | schema 1 迁移、损坏配置、源身份变化、二维三维切换、五语和键盘操作 |
| 性能 | 网格生成、空间索引、上传和相机帧分别统计；验证旋转不重建网格及模型实例共享 |

工程尺寸使用源参数验证；网格只能在指定精度内逼近解析形状。几何正确、GPU 像素正确和实际窗口可操作分别验收。

每阶段提供小型可公开分发的合成样例、实际窗口截图或短录屏和简短复现步骤。公开材料不包含私有设计、模型路径或原始运行日志。开发命令和平台检查沿用[开发与验证](development-progress.md)及[验证方法](validation-guide.md)。
