# 开发与验证

项目处于开发阶段，现有功能包括本地文件导入、图层控制、网络与元件搜索、对象属性查看、多文档、最近文件及查看偏好保存。文件版本差异、显示精度、大型文件性能和各平台稳定性仍需持续验证。

从仓库根目录执行：

```sh
cargo build -p pomelo --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

命令是开发检查入口，不代表当前版本已通过全部验收。GPU、窗口交互、DPI 和输入法需要在目标平台实机检查；构建或单元测试通过不能替代这些检查。

验证优先使用合成几何。报告问题时提供版本、平台、复现步骤及必要诊断；提交前移除设计数据、本地路径和其他敏感信息。公开样本应具备明确的分发许可。

## 验证层次

| 范围 | 检查内容 | 可说明的结论 |
| --- | --- | --- |
| 核心逻辑 | 几何、相机、搜索、选择和状态序列化 | 对应算法及数据边界 |
| 导入 | 输入检查、诊断、取消和场景转换 | 已覆盖输入的处理行为 |
| 渲染准备 | 批次、裁剪、预算和缓存失效 | CPU 场景准备行为 |
| GPU | 着色器、像素、图层合成和设备恢复 | 当前设备及后端的绘制行为 |
| 桌面交互 | 菜单、键盘、焦点、保存和退出 | 实际窗口下的操作行为 |

未显式运行的硬件或外部输入测试不计为通过。历史测试数量和单块设计的性能数据不作为当前版本的验收结论。

## 开发入口

核心测试包含 `camera_navigation`、`search_scene`、`search_collation`、`component_groups`、`curve`、`copper_mesh` 和国际化资源检查。渲染单元测试按场景、文字及平台后端组织。

针对修改先执行最接近的测试；跨模块接线或发布前再执行工作区检查。界面和 GPU 变更还需目标平台实机检查，方法见[验证指南](validation-guide.md)。
